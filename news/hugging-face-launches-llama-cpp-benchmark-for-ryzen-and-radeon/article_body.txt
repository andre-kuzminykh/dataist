# Hugging Face launches llama.cpp benchmark for Ryzen and Radeon

## What the dashboard shows

In the Configuration sidebar, users can select hardware, a model and a llama.cpp build. The options currently include Radeon 8060S (gfx1151) and Radeon AI Pro R9700S (gfx1201).

The Overview tab compares quantization formats for the selected hardware, model and build. Build history shows PP512 and TG128 results across all recorded builds for the selected parameters. The Context scaling tab tracks how token-generation speed changes as the existing context grows.

The benchmark has two separate tests, both measured in tokens per second. PP512 measures processing 512 input tokens without generating any output, while TG128 measures the generation of 128 tokens with no prior context. In both tests, the context depth starts at `n_depth=0`, and the charts show the average speed, `avg_ts`. These are representative workloads for comparison; the Context scaling tab also shows generation speed as the context grows.

## How the tests are run

The tests cover prebuilt executables distributed through `llama-install.sh`, a build-and-install project associated with llama.app. Public test runs for gfx1151 and gfx1201 take place weekly. They use the standard tests from the `llama-bench` utility, with Flash Attention both enabled and disabled; each configuration is run 10 times.

The model list changes. It currently includes Inkling 2 Mini, Qwen, Gemma, gpt-oss and LFM models. The set covers dense architectures and mixture-of-experts architectures. Available GGUF formats include Q4_K_M, Q8_0 and other quantization options, as well as higher-precision BF16 and F16 formats.

## How to explore and use the results

The dashboard pulls data directly from the public `ggml-org/install.sh-benches-data` repository on Hugging Face. The source link beside a chart title opens the folder for the selected build, hardware and model.

Standard results are stored in files in the form `<build>/<hardware>/<model>/<quant>.jsonl`. Tests that vary the context use the `<quant>-tg.jsonl` file in the same folder. The data can be explored, used to create custom charts and compared with results from local runs.

AMD’s team provided the test infrastructure and helped check the setup. The dashboard’s authors invite suggestions for models and workload scenarios to add.

Dataist’s take: the open structure of the results makes it possible to check not only the final numbers but also how the tests are set up. The dashboard covers specific models, builds and hardware configurations, so its results are useful for comparisons within that set but do not provide a universal assessment of AMD’s performance.
