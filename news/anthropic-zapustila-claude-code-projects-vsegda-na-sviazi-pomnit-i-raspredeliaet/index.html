Anthropic запустила Claude Code Projects — «всегда на связи» помнит и распределяет долгую разработку

@neuronium_ai

17 сентября Anthropic представила Claude Code Projects — ИИ-координатора для пользователей Claude Code, который помогает вести длительную разработку приложений, сайтов и других проектов. Он постоянно хранит общий контекст, делит задачи на параллельные потоки и координирует их между сессиями. Бета-версия доступна отдельным подписчикам Claude Pro и Max, работающим с облачными сессиями Claude Code. Позже доступ расширят на других пользователей этих тарифов, а затем — на Team и Enterprise.

Новый Claude Code Projects — это ИИ-агент на базе Claude, который, по словам Anthropic, работает постоянно. Разработчик описывает текущую задачу обычным языком, а система разбивает её на параллельные потоки, чтобы ускорить работу. Затем Claude Code Projects координирует эти потоки, сохраняет общую память проекта и обновляет её по мере развития разработки.

Раньше при продолжении проекта в нескольких сессиях пользователю приходилось самостоятельно хранить отдельную запись о состоянии работы и передавать её Claude Code заново. Другой вариант — попросить Claude Code найти сжатую версию прошлого разговора, повторно изучить актуальное состояние проекта и восстановить, на чём остановилась предыдущая сессия и что требуется сейчас.

Для компаний такой подход особенно подходит для цифровых витрин, сайтов, систем управления контентом, платформ закупок и других бизнес-приложений. У них обычно нет раз и навсегда завершённой разработки: системы годами обновляют, исправляют, расширяют и адаптируют.

Вместо того чтобы каждый раз запускать новую сессию Claude Code и заново восстанавливать контекст, принятые решения и текущее состояние проекта, разработчик сможет сохранять общий контекст работы в Claude Code Projects. Система будет учитывать уже сделанное, координировать новые задачи и помогать продолжать работу с того места, где остановились предыдущие потоки.

При этом названия продуктов могут запутать. У Anthropic уже есть отдельная функция Claude Projects, впервые представленная в июне 2024 года. Это универсальное рабочее пространство Claude для группировки чатов, файлов, инструкций и знаний о проекте. В Claude Projects можно вести несколько чатов и сохранять общие знания, но каждый чат остаётся отдельным разговором: сведения из одного автоматически не переходят в другой, если их не сохранить в знаниях проекта или памяти.

Новый Claude Code Projects, представленный 17 сентября, называется похоже, но решает другую задачу — координирует разработку с участием ИИ-агентов в нескольких сессиях Claude Code. Бета-версия сначала доступна отдельным подписчикам Claude Pro и Max, использующим облачные сессии Claude Code и ещё не имеющим Projects в веб- или настольной версии.

Anthropic обещает в течение следующей недели открыть доступ большему числу пользователей Claude Code на этих тарифах. Позже обновлённый формат появится у более широкой аудитории Claude, включая Team и Enterprise. Существующие Claude Projects на тарифах Pro и Max во время развёртывания продолжат работать как прежде.

Сдвиг связан с тем, что агенты для программирования всё чаще справляются с задачами, выходящими за пределы одного промта или запроса на включение изменений в репозиторий.

OpenAI, GitHub и Google уже переходят к асинхронным, параллельным и длительным рабочим процессам с ИИ-агентами.

Anthropic рассчитывает, что разработчикам нужен не просто ещё один сеанс программирования, а постоянный координационный слой над несколькими сессиями. Он должен помнить общую цель и распределять работу между ними.

В публикации на X Anthropic сравнила такое взаимодействие с постановкой задач руководителю аппарата: пользователь может передать Claude несколько поручений сразу и в любом порядке, а Claude сам решит, относится ли каждое из них к новому или уже существующему потоку.

От отдельных сессий к общей разработке

Разработчикам, которые используют несколько агентов для программирования, часто приходится самостоятельно делить крупную функцию на отдельные задачи, задавать контекст для каждой сессии, а затем сводить результаты. Claude Code Projects должен перенести значительную часть этой координации в Claude.

Проект Claude Code хранит общую цель и контекст, одновременно создавая отдельные потоки выполнения для разных частей работы. В финальной публикации о запуске Anthropic описала архитектуру так: потоки выполняют работу, а Claude руководит ими. Над рабочими потоками в каждом проекте находится координатор.

Разработчик может продолжать общение с координатором по мере изменения требований, не дожидаясь завершения одной задачи перед запуском другой. Claude способен направить новый запрос в существующий поток или создать дополнительный. При необходимости пользователь может открыть конкретный поток, чтобы проверить или направить выполняемую там работу.

В Claude Code Projects также есть панель обзора с задачами, требующими внимания пользователя. В публикации на X Anthropic сообщила, что разработчики смогут управлять отдельными потоками с телефона. Человеку не придётся держать все сессии Claude Code открытыми на рабочем компьютере.

Основной единицей взаимодействия становится не изолированная задача по программированию, а длительная работа над проектом.

Например, разработчик может создать проект Claude Code с целью сократить значение p75 для задержки оформления заказа в приложении. Claude создаст параллельные потоки, которые будут профилировать конечные точки, проверять оптимизации и открывать запросы на включение изменений в репозиторий.

В другом случае команда может подключить репозитории API, веб- и мобильного приложений и попросить Claude удалить устаревшую конечную точку версии 1. Отдельные потоки перенесут вызывающий её код и протестируют каждый репозиторий, а координатор будет отслеживать зависимости и сообщать разработчику, какие изменения нужно объединить первыми.

Каждый рабочий поток — отдельная облачная сессия Claude Code, работающая со своей веткой и копией репозитория. Потоки могут дополнительно делить поручения с помощью субагентов, циклов и рабочих процессов. Координация не устраняет обычные конфликты разработки: если несколько потоков меняют пересекающиеся участки кода, могут возникнуть стандартные конфликты слияния. Их разрешают так же, как в других запросах на включение изменений.

Общая память сохраняет состояние проекта

Параллельное выполнение само по себе уже не редкость среди агентов для программирования. Более важной частью Claude Code Projects может оказаться состояние, которое сохраняется над отдельными сессиями.

Каждый рабочий поток добавляет сведения в общую память проекта и использует её. В ходе длительной работы Claude может сохранять решения о переносе даты выпуска, отказе от функции или о том, с кем нужно посоветоваться перед изменением конкретного сервиса. Anthropic также позволяет настроить частоту сообщений Claude, создания новых потоков и подробность обновлений.

В Claude Code Projects есть библиотека, куда попадают предоставленные пользователем файлы и созданные Claude материалы. Благодаря этому последующие задачи получают постоянный набор данных для работы. Для проекта можно отдельно настроить облачное окружение, подключения, плагины, инструкции и параметры модели.

Это связано с концепцией базы знаний в Claude Projects, но отличается от неё. Claude Projects используют загруженные знания и инструкции, чтобы задавать контекст разговоров. Claude Code Projects добавляет общую рабочую память для потоков: решения, принятые во время одной части инициативы, могут влиять на последующую работу в другом месте проекта.

Для корпоративных инженерных команд это различие может быть не менее важным, чем возможность запускать больше агентов. Проблема всё чаще заключается не только в том, способен ли агент исправить ошибку или реализовать функцию. Нужно также сохранять требования, зависимости, прежние решения и контроль человека, пока несколько агентов работают одновременно.

Разницу можно свести к двум пунктам:

Claude Projects помогает Claude помнить контекст, который передал пользователь.
Claude Code Projects должен помогать Claude помнить и координировать выполняемую им работу.

Конкуренция переходит от агентов к координаторам

Anthropic не единственная компания, которая заметила проблему координации. OpenAI, GitHub и Google тоже отходят от модели, в которой разработчик работает с одним агентом для программирования в одном линейном разговоре.

Всё важнее становится то, как разработчик распределяет набор задач, сохраняет контекст, наблюдает за параллельными агентами и добавляет новые требования, не превращаясь в диспетчера между ними.

Ближайшее прямое сравнение — продукт OpenAI. Приложение Codex задумано как многопользовательское рабочее пространство для программирования, где можно параллельно запускать несколько агентов, изолировать их изменения и контролировать длительную работу. С Claude Code Projects его роднит то, что параллельные агенты становятся обычным сценарием, а не продвинутым режимом.

Отличительная особенность опубликованной Anthropic архитектуры — отдельный координатор над рабочими потоками. Разработчик продолжает общаться с одним проектом Claude Code, а Claude сам решает, направить ли новую инструкцию в существующий поток или создать новый. Anthropic также прямо описывает общую память, охватывающую эти потоки.

Поэтому отличие Claude Code Projects не в уникальной поддержке параллельных или длительных задач. Конкуренты уже предлагают и то и другое. Более конкретная идея Anthropic — сделать постоянный разговор с координатором главным интерфейсом для управления несколькими сессиями.

GitHub подходит к проблеме с другой стороны: его преимущество — сам репозиторий и процесс разработки. Инструменты GitHub для агентов поддерживают несколько изолированных сессий и тесно связывают их с ветками, задачами, запросами на включение изменений и рабочими процессами непрерывной интеграции. Это даёт GitHub преимущество там, где репозиторий уже является главным центром управления разработкой.

Anthropic пытается разместить разговорный координационный слой над отдельными репозиториями и сессиями. В её примере с удалением устаревшей конечной точки один координатор Claude Code Projects отслеживает общую миграцию и порядок объединения изменений сразу в репозиториях API, веб- и мобильного приложений.

Google предлагает третий вариант — Jules. Он поддерживает асинхронную разработку и память на уровне репозитория, поэтому последующие задачи получают доступ к накопленным в нём предпочтениям и рекомендациям.

Claude Code Projects поднимает постоянную память на уровень более широкой инициативы: несколько рабочих потоков могут использовать одну общую память и оставаться под управлением одного координатора.

Продукты постепенно получают одни и те же базовые возможности — параллельное выполнение, изолированные окружения, асинхронную работу, память и вмешательство человека, — но размещают центр управления в разных местах.

OpenAI делает акцент на многопользовательском рабочем пространстве для программирования. GitHub — на выполнении и контроле внутри репозитория. Google Jules — на постоянной асинхронной работе вокруг репозитория. Claude Code Projects превращает один длительный разговор о развитии инициативы в координационный слой.

Сейчас — облако, позже — локальная работа

Рабочие потоки Claude Code Projects сейчас выполняются в облаке. Поэтому они продолжают работу после закрытия ноутбука или отключения разработчика от сети. Однако в публикации Anthropic отдельно указала ограничение: облачные потоки пока не могут обращаться к файлам и инструментам на компьютере разработчика или к системам во внутренней сети.

Anthropic обещает «очень скоро» добавить локальную поддержку. Тогда Claude Code Projects сможет работать вместе с локальным кодом и инструментами, в том числе внутри сети организации.

Это особенно важно для компаний, чьи среды разработки зависят от закрытых пакетов, внутренних сервисов, ограниченных сетей или локальных инструментов, которые нельзя открыть облачному окружению выполнения.

При этом Anthropic уже позволяет управлять текущей работой с телефона, пока рабочие сессии выполняются удалённо. Мобильное устройство становится поверхностью для контроля, а рабочий компьютер больше не обязан оставаться включённым.

Anthropic не вводит отдельную плату за Claude Code Projects. Проекты используют имеющийся у подписчика лимит Claude, а каждый рабочий поток является полноценной сессией Claude Code. Поскольку проект может одновременно запускать несколько потоков, Anthropic предупреждает: лимиты использования могут закончиться быстрее. Пользователь сможет посмотреть расход отдельно по проекту и выбрать модели и уровни усилий для координатора и рабочих потоков.

Конкуренция всё дальше уходит от вопроса, способен ли ИИ-агент писать код. OpenAI, GitHub, Google и Anthropic уже могут запускать агентов асинхронно и параллельно.

Сложнее становится определить, кто координирует этих агентов, где сохраняются накопленные ими решения и куда разработчику обращаться для управления работой, которая может продолжаться дольше любой отдельной сессии.

В Claude Code Projects Anthropic предлагает один непрерывный разговор с координатором: разработчик сообщает ему новые требования по мере развития инициативы, общая память переносит решения дальше, а меняющийся набор рабочих потоков Claude Code выполняет задачи.

Это отличается от существующего Claude Projects, который пока остаётся универсальным рабочим пространством для организации чатов, файлов, инструкций и знаний.
