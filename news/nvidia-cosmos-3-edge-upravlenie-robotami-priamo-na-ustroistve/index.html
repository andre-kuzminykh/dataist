NVIDIA Cosmos 3 Edge: управление роботами прямо на устройстве

NVIDIA выпустила Cosmos 3 Edge — компактную модель мира для управления роботами непосредственно на устройстве. Модель включает 4 млрд параметров и рассуждатель на базе NVIDIA Nemotron с 2 млрд параметров, а её политика управления запускается на Jetson Thor без подключения к серверному GPU. В тестах замкнутого цикла RoboLab дообученная политика достигла 22,9% успешных выполнений. NVIDIA также опубликовала открытый программный каркас, контрольную точку на Hugging Face и пошаговое руководство по обучению и запуску.

Что такое Cosmos 3 Edge

Роботам нужны политики, которые умеют подстраиваться под датчики, окружение и задачу и при этом работать на бортовом компьютере. Модели мира дают основу для изучения физических взаимодействий, но их размер часто мешает запускать их непосредственно на роботе.

Cosmos 3 Edge входит в семейство Cosmos 3. Это мультимодальная модель на 4 млрд параметров с рассуждателем NVIDIA Nemotron на 2 млрд параметров. Её предварительно обучали на тех же данных о физическом мире, что и NVIDIA Cosmos 3 Nano и NVIDIA Cosmos 3 Super. Поэтому Edge начинает с тем же представлением о том, как объекты двигаются и взаимодействуют друг с другом, но при этом достаточно мала для запуска на NVIDIA Jetson Thor.

В руководстве NVIDIA показано, как дообучить Cosmos 3 Edge для манипуляций, запустить политику на Jetson Thor и проверить её в симуляции с замкнутым циклом. Все шаги можно воспроизвести в открытом хранилище кода cosmos-framework, а готовая контрольная точка доступна на Hugging Face.

Модели мира для управления роботами

Базовые модели мира предварительно обучают на больших мультимодальных наборах данных. В них фиксируются закономерности движения объектов и физических взаимодействий: например, как предметы падают, скользят и реагируют на контакт.

Cosmos умеет генерировать действия на основе понимания и предсказания физических процессов. Эти знания дают отправную точку для обучения политики управления роботом: ей не нужно с нуля осваивать все физические связи только по демонстрациям конкретной задачи.

При запуске таких моделей на физическом роботе возникают два практических ограничения. Дообучение Cosmos 3 Edge учитывает оба из них. Получившаяся политика помещается в память Jetson Thor, поэтому инференс выполняется прямо на роботе, без передачи вычислений на GPU в центре обработки данных.

Остаётся вопрос задержки управления. Политика DROID работает в реальном времени непосредственно на роботе. На NVIDIA Jetson AGX Thor T5000 она формирует каждый блок действий примерно за 1,53 секунды при разрешении 640×540 и частоте 15 Гц. Один такой блок рассчитан примерно на 2,13 секунды движения робота.

Поскольку следующий блок готов до завершения текущего, рука движется непрерывно. Политика поддерживает потоковую работу на устройстве: после каждого цикла инференса она создаёт новый блок действий и заново планирует движение. При этом перепланирование происходит не после каждого наблюдения.

В задачах RoboLab с замкнутым циклом дообученная политика достигла 22,9% успешных выполнений. Эти результаты показывают, что модель мира на 4 млрд параметров может работать как основа практичной политики управления в реальном времени непосредственно на устройстве. Cosmos 3 Edge помещается в Jetson AGX Thor и полностью выполняется на роботе.

Данные для обучения

Политика из руководства обучается на наборе данных nvidia/Cosmos3-DROID. В нём 76 тысяч успешных траекторий телеуправления — примерно 350 часов данных, собранных для 86 задач и 564 сцен. В экспериментах использовались рука Franka Panda и захват Robotiq.

Набор данных поставляется в формате LeRobotDataset v3.0 с разрешением 640×360.

Подготовка проходит в три этапа. Сначала данные переводят в формат LeRobot Dataset v3: для каждого кадра нужны видео с камеры, состояния суставов, состояние захвата, действия и инструкция к задаче.

Для конфигурации с рукой Franka, похожей на DROID, главным изменением будет путь к набору данных. Для другой роботизированной платформы потребуется отдельная конфигурация эксперимента, в которой задаются пространство действий, его размерность, схема размещения камер и параметры нормализации.

Cosmos 3 поддерживает несколько вариантов роботов, включая двухрукую систему на базе Franka, UR, WidowX 250 и LeRobot SO101. Полный список конфигураций приведён в карточке модели Cosmos 3 Edge.

Ресурсы для дообучения

Речь идёт о дообучении базовой модели, а не о тонкой настройке на одной GPU. Проверенный запуск использует 64 узла по 4 GB200, 60 тысяч итераций и занимает около 68 часов — примерно 17,4 тысячи часов работы GB200. Вычислительные ресурсы нужно планировать с учётом этих требований.

На верхнем уровне дообучение разделено на четыре шага. В руководстве исходный файл запуска регистрирует рецепт для Cosmos 3 Nano. Перед запуском обучения Cosmos 3 Edge в нём нужно изменить три параметра.

Остальные настройки — набор данных, пространство действий, фильтр отбора и расписание обучения — остаются прежними.

Актуальные инструкции полного цикла, включая преобразование контрольной точки, настройку окружения и конфигурацию фильтра отбора, NVIDIA предлагает искать в руководстве по воспроизведению дообучения DROID и в карточке модели. Эти материалы обновляются вместе с хранилищем кода.

Запуск политики на роботе

Политика работает через сервер на основе протокола WebSocket, который использует протокол OpenPI. Этот же протокол применяется во всей экосистеме политик DROID. Клиент отправляет словарь наблюдений, а сервер возвращает блок действий.

Для Cosmos 3 Edge сервер запускается непосредственно на Jetson Thor. В формате BF16 веса занимают примерно 9 ГБ и помещаются в бортовую память Thor, поэтому сервер политики и клиент управления работают на самом роботе, без GPU в центре обработки данных.

Сервер использует адрес `host="localhost"`, поэтому запросы не покидают устройство. Политика выполняет инференс в реальном времени — это и есть локальный запуск, который обеспечивает Cosmos Edge.

Политика DROID учитывает текущее состояние робота. Поэтому `joint_position` и `gripper_position` — полноценные входы модели, а не формальные поля запроса. Если рука не подключена, в качестве честной заглушки можно передать нулевые значения. Такой вызов лишь проверяет, что сервер возвращает корректно сформированный блок действий.

Тот же вызов используется в цикле перепланирования. На каждом шаге система получает свежие изображения с камер, измеренные положения суставов и захвата, выполняет часть блока действий, а затем снова обращается к политике.

Выполнение только части блока с последующим перепланированием позволяет политике самостоятельно корректировать движение каждые несколько секунд. Поскольку она учитывает состояние робота, новый план начинается с фактического положения руки, а не с того, которое предполагал предыдущий блок.

Если запустить сервер с включённым декодированием видео, вместе с действиями он возвращает смоделированную моделью траекторию. Так можно посмотреть, какое развитие событий Cosmos предсказывает для созданного блока.

Проверка в симуляции

Для проверки политики физический робот не нужен. NVIDIA рекомендует сначала оценивать её в симуляции, чтобы неожиданные действия не повлияли на разработчиков или оборудование.

RoboLab — открытый бенчмарк на базе Isaac Lab-Arena, который используется в рейтинге RoboLab. Его клиент подключается к тому же серверу политики, выполняет каждый блок действий в физической симуляции и передаёт обратно визуализированные наблюдения. В результате формируется настоящий замкнутый цикл для 120 задач по манипуляциям, заданных естественным языком.

Параметр `--task` можно заменить на любую из 120 задач, чтобы получить более широкую картину поведения политики. Каждый запуск создаёт видео из окна симуляции и с камеры робота, а также журнал успешности. Это позволяет проверить и результат, и траекторию, которая к нему привела.

В замкнутой оценке RoboLab политика Edge достигла 22,9% успешных выполнений по всему набору задач. Для сравнения, Cosmos 3 Nano показала 36,8%. Edge рассчитана на компромисс между результативностью и вычислительными затратами инференса: она обеспечивает работу в реальном времени полностью на роботе.

Для NVIDIA Isaac Sim 5.x требуется драйвер NVIDIA RTX Server версии 580 или новее. Перед сборкой окружения нужно проверить поддерживаемую версию в документации RoboLab и Isaac Sim.

Другие применения

Методы дообучения, которые улучшают управление роботами, можно использовать и для других задач — например, для создания синтетических данных.

Разработчики могут создавать специализированные модели мира, генерирующие качественные синтетические данные с учётом конкретного окружения и задач. Такие данные подходят для обучения роботов, работающих внутри помещений и на улице.

В качестве примера NVIDIA приводит Aigen. Компания дообучила Cosmos для генерации разнообразных вариантов сельскохозяйственных культур и сорняков. Благодаря этому автономная система прополки смогла добиться высоких результатов, используя для обучения только 1% реальных данных.

Открытые веса Cosmos и программный каркас под лицензией OpenMDW1.1 позволяют дообучать модели под конкретные задачи физического ИИ и создавать специализированные модели.
