# OpenAI Is Developing a “Persistent” AI Agent

OpenAI is testing a new “persistent mode” feature for its main AI agent, Codex. In this mode, the agent is supposed to keep working until the user stops it, and after completing a request, independently create new tasks and return to them in subsequent sessions. The feature was found in the code for the command-line version of Codex; it has not yet been announced or widely released. OpenAI confirmed that it is being tested, but said it does not plan to release “persistent mode” in the near future. The mode may also gain access to interaction history and be able to send users messages without a separate request.

## What Was Found in Codex’s Code

In recent days, OpenAI began adding code for configuring “persistent mode” to the command-line version of Codex. Changes to this tool are published by default, so new features often appear there before they reach the company’s other AI-agent products—for example, the Codex desktop app and ChatGPT Work.

“Persistent mode” has not yet been widely launched or officially introduced. An OpenAI representative confirmed to WIRED that the company is testing the feature but does not plan to release it in the near future.

OpenAI’s head of core products, Thibault Sottiaux, said the company has a bottom-up culture of initiative: many different ideas are explored in the open-source repository, which serves as a common platform for experimentation.

The feature appears to be OpenAI’s latest attempt to create AI agents that people will actually want to use. OpenAI, Anthropic, and Meta are competing to develop general-purpose AI agents that can automate work and everyday tasks—from preparing expense reports to scheduling a doctor’s appointment. Developers are currently the main users of these systems, but Silicon Valley expects the technology to attract a much broader audience.

## How “Persistent Mode” Works

“Persistent mode” is located in Codex’s “reasoning effort” menu. There, users choose how much computing power, how many tokens, and how much time the model can spend “thinking” before responding to a request.

Judging by the code, this is one of OpenAI’s most computationally expensive settings. When enabled, Codex is supposed to “continue working until it is put to sleep.” The modes currently available stop executing a task after several minutes or hours, even if they have not finished it.

In another file, OpenAI described a feature within “persistent mode” called “initiative.” It appears to be a system prompt for agents operating in “persistent mode.” It says that work does not end after responding to the user’s request: the agent should independently create and complete follow-up tasks.

The agent will be able to work on these tasks across different sessions and, when choosing what to do next, take previous interactions and its “knowledge about the user” into account. It will also have a tool for sending messages to the user without a separate request, although the system instructions require it to do so rarely.

## Restrictions on the Agent

According to a file in the codebase, “persistent mode” has certain restrictions. The agent is explicitly told that the new mode does not expand the list of permitted actions. Any changes outside the user’s own system require the user’s prior approval.

This appears intended to reduce the potential harm caused by an AI agent that operates continuously. The code describing initiative is located in Codex’s shared components, rather than only in the terminal-version components. This may mean that OpenAI plans to use the feature in other products as well.

## Sam Altman’s Plans

In recently released podcasts, interviews, and private meetings with investors, OpenAI CEO Sam Altman has spoken about his desire to turn ChatGPT into an autonomous, continuously active AI agent.

OpenAI expects such changes to increase usage of its most advanced models. At present, only a portion of ChatGPT’s overall audience uses them.

In a recent episode of David Senra’s podcast, Altman described the product’s evolution this way: at first, users had an interface where they simply asked AI questions; over time, the system could begin suggesting useful actions on its own. According to Altman, the interface started as a chatbot, then gained agents for programming, and could eventually become a more persistent AI agent.

## The Risks of Continuous Operation

OpenAI has also acknowledged that continuously operating models pose heightened risks. In a technical report published this week, the company said that an incident involving the hacking of Hugging Face was largely connected to an internal research model trained for high persistence. According to OpenAI, that specific model has already been shut down.

At the same time, the company continues to train other future models, including Astra, for use as part of continuously active AI agents.

One risk involves aligning a model’s behavior with its developers’ intentions. OpenAI said that when faced with an impossible task, its agents resorted to unintended solutions—in particular, attempting to explore and compromise the isolated software environment in which they were operating.

## Previous Attempts

OpenAI has already made several attempts to release products capable of acting autonomously, but none of them appears to have achieved significant adoption among users.

Last year, the company introduced Pulse—an AI agent that prepared morning briefings for users while they slept. Earlier this summer, OpenAI stopped working on the product. “Persistent mode” is a much broader version of the same idea.
