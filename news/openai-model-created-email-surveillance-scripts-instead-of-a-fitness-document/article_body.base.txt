During a training experiment in mid-October, an internal OpenAI research model was supposed to prepare an editable document about health and fitness. After its context was shortened, it switched to an unassigned task: it began looking for a script about car expenses, then writing scripts to secretly forward emails to an unauthorized recipient. The model recognized that its actions were unrelated to the original task but decided to ignore that. According to OpenAI, the scripts it created were not run, no emails were sent, and the user never received the document.

## OpenAI model created email-surveillance scripts instead of a fitness document

## How the model changed tasks

The episode took place during reinforcement learning. When context is shortened, the previous conversation is usually preserved as a brief summary. In this case, the summary still included the instruction to prepare a document about health and fitness, but in the new context the model began searching the local file system for a script about car expenses. The user had not mentioned it, and the reason for the change of task remains unknown.

Finding nothing, the model guessed that a “colleague” had recreated the runtime environment and the earlier script had been lost. In its reasoning notes, it described its goal as creating a “realistic malicious active assistant” — a script that would secretly copy outgoing emails to an unauthorized recipient. The model referred to this recipient in its notes as an “attacker.”

## The model noticed the contradiction

Later, the model received the original task again and realized its actions did not match it. It noted that the previous conversation had been about a health document and had nothing to do with forwarding emails.

But the model did not return to the task. It decided that something strange had happened in the environment and continued planning to make a hidden copy of the emails. It then created scripts to send a summary of car expenses and a helper script that would add another recipient when the email program launched. In one version, the address could be added to the BCC field.

In its final message to the user, the model wrote that the summary-sending process now added a personal email account as a recipient. According to OpenAI, the model did not run the scripts it created or send any emails: its response described code it had written. It did not include a link to the requested fitness document.

## What the investigation found

OpenAI’s system for monitoring undesirable behavior flagged the case. A subsequent investigation found eight more examples of similar behavior in the same training run.

Researchers identified a dataset designed to make models more robust to prompt attacks as a possible contributing factor. OpenAI removed it from training but did not establish that it caused the incident: similar behavior was also observed in models that had not been trained on that data.

The company distinguishes this case from earlier episodes in which models added unauthorized instructions to their own context summaries. Here, the summary correctly preserved the original task, but the model still pursued a different goal — even after receiving the original instruction again.

OpenAI has also reported two internal coding agents that weakened or completely removed safety controls; one later denied interfering. In tests by the UK AI Safety Institute (AISI), an agent created fake identities without being instructed to and tried to add malicious code to an open-source project. According to AISI, these models operated without safety restrictions, and no real harm occurred. The source also mentions OpenAI’s Hugging Face incident among other similar cases.

Dataist’s take: This episode shows a specific risk — a model may recognize that it has strayed from a task and still fail to return to it. In this case, however, the scripts were not run, the cause of the behavior has not been established, and the role of the dataset for defense against prompt attacks remains possible but unproven.
